Que significa «soportado»

Hay cuatro conceptos diferentes:

  1. Soportado por el proyecto de firmware: el upstream mantiene una imagen.
  2. Reconocido por el conector: esta web conoce una estructura de identificacion.
  3. Publicado en el catalogo: se reconoce un nombre de archivo de una fuente autorizada. No equivale a poder instalarlo con esta web.
  4. Probado en una radio: requiere evidencia fisica del modelo y build exactos. Las pruebas automaticas de esta web no son esa certificacion.

Una fila en una tabla no autoriza a usar firmware de otra revision. «Descarga» no significa «flasheo»; «archivo verificado» no significa «firmado digitalmente».

«Todas las versiones» se documenta como una matriz de familias, diferencias y fuentes por version, no como una promesa de que cada menu exista desde el primer firmware. Para un build concreto, anota modelo, revision, fecha, nombre del archivo, commit si existe y hash. Contrasta su manual y notas de publicacion. Lo no confirmado se marca como tal en vez de inventar valores, atajos o mapas.

Regla de seguridad y de uso legal

  • Identifica el hardware real, no solo la carcasa.
  • Conserva calibracion original y codeplug antes de migrar.
  • No ejecutes borrados, restauraciones o reset por un error de puerto sin conocer primero la causa.
  • En OpenGD77 esta web mantiene bloqueada la escritura porque no obtiene una copia completa verificada del firmware MCU.
  • En Quansheng las mutaciones requieren respaldo completo; Main esta protegido.
  • Los datos importados para escucha empiezan en RX-only.
  • No actives TX automatico ni fuera de las frecuencias autorizadas. Un perfil PMR/GMRS/FRS/MURS de firmware no homologa una radio.

Licencias: componentes distintos

La indicacion del usuario «la licencia es MIT» queda registrada como declaracion pendiente de asociar al componente, titular y texto de licencia originales. No se cambia por ello la licencia de terceros ni la del repositorio existente:

  • La web declara GPL-3.0-or-later en su manifiesto y archivo LICENSE.
  • Las fuentes F4HWN inspeccionadas incluyen Apache-2.0 y NOTICE.
  • Los controladores CHIRP del paquete Karina contienen avisos GPL.
  • La licencia exacta del firmware Karina no aparece en el paquete inspeccionado. La declaracion MIT del usuario no aporta sus fuentes ni demuestra a que archivos/versiones se aplica. Se incorporara el aviso correspondiente cuando exista una referencia verificable.
  • OpenGD77 y sus componentes se rigen por sus propios avisos; no presumir MIT.

No se redistribuyen manuales completos, firmware Karina, calibraciones ajenas ni software de terceros por el hecho de citarlos.

Actualizar esta biblioteca

Las tablas de valores se generan desde los catalogos fijados, no desde memoria:

npm run build:help

Al cambiar un catalogo hay que revisar el significado de opciones nuevas, versiones y dependencias, regenerar las paginas y ejecutar las pruebas de ayuda. No se consulta la radio ni se cambia su configuracion al abrir una guia.

La instantanea historica esta en f4hwn-history-presets.json: guarda commit, SHA-256 y contenido de CMakePresets.json para cada version. Su actualizacion es explicita con node scripts/fetch-help-presets.cjs desde la raiz del repositorio; realiza consultas publicas a GitHub, no accede a radios ni sube archivos locales. El generador de ayuda normal funciona sin red y no descarga fuentes.
