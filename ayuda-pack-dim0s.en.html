Dim0s pack: inventory and Karina V3/UV-K1

Revision: 25-10-2026. Repository supplied by the user: Dim0s/quansheng-UV-K5v3-K1-firmware-pack. Inspected commit: 52b41c182dd82c1fbdc027dc2da7bbcb02c7d79c.

What changed since the previous inspection

The local Karina package initially reviewed was V1. This repository announces firmware for K5 V3, K1, and devices with bootloader 7.x and contains another Karina package with separate K1/V3 binaries. Therefore:

  • It is incorrect to claim that only Karina V1 exists.
  • It remains correct to reject the earlier package's V1 binary for V3.
  • There is new evidence of Karina PY32 binaries, but not that they are compatible with Armel multiboot or that their sources are available.
  • This reference does not make the pack an official source for each author.

The repository header recommends saving calibration. Its Karina information says there is no link to the source repository and describes it as closed firmware, with builds reposted in an external channel. This alone does not prove a specific license: the MIT notice stated by the user still needs a verifiable source/rights holder.

Nature and limits of the inventory

The complete, untruncated Git tree contains binaries, apps, documents, Python drivers, and compressed files. No .c/.h source files, Makefile, or LICENSE/COPYING/NOTICE by name were found in that tree. We do not claim to have inspected every ZIP/RAR internally in the repository. The 21-09-2026 ZIP for Karina was inspected, without running its files.

The pack is not copied into the web repository; EXE, APK, drivers, and calibrations are not installed. Its PDFs, files, and firmware are not redistributed. A locally calculated SHA-256 hash detects changes from that download but does not establish authorship, license, safety, or correspondence to source code.

Multiboot: claim versus verification

The maintainer lists F4HWN, GOGU, IOTCU, and N7SIX as compatible with Armel multiboot, along with external Sonic. Karina is not on that list. Format, map, identification, CFG banks, restoration, protocol, integrity, and hardware boot must be checked before expanding the inspector.

The website retains its list of recognized F4HWN images. No string is modified and no file is renamed to bypass it. These sources are not automatically added to the verified-download catalog for original authors.

  2. Reproducible build and memory map.
  3. Specification/protocol and real CFG/calibration compatibility.
  4. Verification of the multiboot mechanism or a demonstrated compatible

implementation.

  1. Physical read, backup, boot, restoration, and recovery tests.
