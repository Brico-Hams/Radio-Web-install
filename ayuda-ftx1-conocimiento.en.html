Yaesu FTX-1 knowledge: research reference

Introduction and safety legend

This document gathers what was learned from 22 public repositories about the Yaesu FTX-1 (CAT commands, USB, memories, firmware, hardware, satellites and remote architectures) and compares it with what Bricohams already does. It is reference material: it does not replace Yaesu's official "CAT Operation Reference Manual" or the user help docs/AYUDA-FTX1.md.

Where the sources are: each repository is cloned unchanged in third_party/ftx1/<carpeta>. The table with the URL, commit and licence of each one is in third_party/ftx1/SOURCES.md. Citations are written [carpeta:ruta], with the folder under third_party/ftx1/. The [SOURCES.md] citations point to third_party/ftx1/SOURCES.md.

Safety legend. These labels mark rows and paragraphs:

  • ESCRIBE EN LA RADIO (WRITES TO THE RADIO): saves data that persists in the radio (memory, menu, clock, state) or changes the state of the radio.
  • REGION/LIMITES TX (REGION/TX LIMITS): changes or affects the bands or the power on which the radio can transmit.
  • CALIBRACION (CALIBRATION): touches factory calibration data.
  • FIRMWARE: reads, prepares or loads firmware.

This project never automates anything marked REGION/LIMITES TX, CALIBRACION or FIRMWARE. It does not automate transmission either (PTT, CW, tuner). Everything marked ESCRIBE EN LA RADIO that the tool does offer (memories, menu) requires reading first, making a backup, simulating and verifying by reading back.

Notation: commands are ASCII terminated by ;. P1 is the side: 0 = MAIN, 1 = SUB, unless stated otherwise. ?; is the radio's rejection. "Set only" means it has no read and no answer. CAT requires MAIN firmware 1.08 or later [gnfrazier-ftxcat:Installation_and_Transceiver_Setup.md] [ew1abz-yaesu-ftx-1-memory-manipulator:doc/cat-version-diff.md]. Three revisions of the CAT manual have been seen: 2306, 2507(-B) and 2508-C [captobie-ftx1-remote:ftx1-cat-manual-errata.md] [ew1abz-yaesu-ftx-1-memory-manipulator:doc/cat-version-diff.md]. The 2508-C manual has 89 command families in the index (90 with EO, which is only in the detail table) and 580 detail rows, 427 of them for EX [rigplane-rigplane-core:docs/validation/cat-audits/ftx1.md].

No studied repository contains code that writes firmware, changes region or TX limits (except the region tool in section 5 and the PC/EX power menus), or writes calibration. Of the firmware, only the version is read, with VE.

USB, serial and audio interfaces

Ports (dual CP210x UART)

  • The USB-C connector exposes an internal hub: a Silicon Labs CP2105 dual UART (VID 10C4 PID EA70; the second serial function shows up as 26AA:0030) and a USB audio codec (VID 0D8C PID 0016) [rigplane-rigplane-core:rigs/ftx1.toml] [captobie-ftx1-remote:CLAUDE.md].
  • Enhanced COM Port = CAT-1 (CAT commands). Standard COM Port = CAT-2 (PTT, CW, DATA or secondary CAT) [gnfrazier-ftxcat:Installation_and_Transceiver_Setup.md] [rigplane-rigplane-core:docs/guide/ftx1-usb-setup.md].
  • Driver: Silicon Labs Dual CP210x USB to UART Bridge; Windows shows "Enhanced COM Port (COMx)" and "Standard COM Port (COMy)". Linux /dev/ttyUSB0/ttyUSB1; macOS /dev/tty.SLAB_USBtoUART; on a Pi, by id, ...CP2105...-if00-port0 is CAT and interface 1 is the keying port [gnfrazier-ftxcat:Installation_and_Transceiver_Setup.md] [captobie-ftx1-remote:Pi/README.md].
  • bg7nzl picks only the "Enhanced COM Port" for CAT and the "Standard COM Port" for PTT (default ports in code COM11/COM12) [bg7nzl-ftx1ctl:docs/user_manual_en.md] [bg7nzl-ftx1ctl:ftx1cat.py].
  • CAT-3 is the rear TUNER/LINEAR UART; it is not needed for USB and it is best to leave TUN/LIN PORT SELECT at its default [gnfrazier-ftxcat:Installation_and_Transceiver_Setup.md] [ew1abz-yaesu-ftx-1-memory-manipulator:doc/cat-version-diff.md].
  • WSL2: usbipd bind/attach of the CP2105 (10c4:ea70) leaves it unusable in Windows [gnfrazier-ftxcat:Installation_and_Transceiver_Setup.md]. On Linux the user has to be added to the dialout group [gnfrazier-ftxcat:faq.md].
  • An undervolted Pi drops the radio's USB hub. cp210x ttyUSB...: failed set request stops CW keying [captobie-ftx1-remote:CLAUDE.md] [captobie-ftx1-remote:Pi/README.md].
  • The audio services fail with "Device or resource busy" if another client holds the sound card [captobie-ftx1-remote:Pi/README.md].

Region tool and TX ranges

Summary only. ESCRIBE EN LA RADIO REGION/LIMITES TX CALIBRACION. This project does not use it, does not automate it and does not reproduce it. For details go to the original repository (https://github.com/Evgeny161rus/ftx1-region-tool, copy in third_party/ftx1/Evgeny161rus-ftx1-region-tool).

What it is. A command-line tool in Python that uses undocumented service commands, present in the MAIN firmware but absent from the CAT manual, to read and write individual bytes of the radio's EEPROM. The bytes it modifies are next to the factory calibration table [Evgeny161rus-ftx1-region-tool:README.md] [Evgeny161rus-ftx1-region-tool:ftx1_region.py]. It only touches the EEPROM through those service commands (SPR read, SPW write); it does not use menus or normal commands.

What it changes, in concept. The radio's destination or region code. The table of bands on which the firmware allows transmitting depends on that code. Changing it widens or narrows the TX ranges; the tool documents different tables per region (narrow for amateur bands, wider, or almost continuous). The tool itself warns that a very wide region can offer ranges where the RF path is not designed to work [Evgeny161rus-ftx1-region-tool:README.md]. It is made for one specific version of the MAIN firmware (V01.13); on other versions you must dump first because the addresses and codes may differ.

The tool's safeguards. A prior EEPROM dump with checksums; an automatic backup before writing (it aborts if it cannot be read); rejection of an unknown current code unless forced; a simulation mode; explicit confirmation; read-back with retries after writing; the radio must be fully powered off and on afterwards [Evgeny161rus-ftx1-region-tool:README.md]. A generic write command can reach any byte, including the calibration [Evgeny161rus-ftx1-region-tool:README.md]. Old versions had a read bug that produced corrupt dumps and backups.

Risks.

  • Loss of calibration: service EEPROM is written next to it; the full prior dump is the only safety net.
  • Legal and type approval: transmitting outside what the licence or the type approval allows is the user's responsibility; changing the region may breach them [Evgeny161rus-ftx1-region-tool:README.md].
  • Warranty: the change may void the warranty [Evgeny161rus-ftx1-region-tool:README.md].
  • The author offers it "as is" and disclaims liability for damage, data loss or malfunction [Evgeny161rus-ftx1-region-tool:README.md].
  • If the firmware restores the code at boot, the repository says that an external programmer and editing a dump would be needed [Evgeny161rus-ftx1-region-tool:README.md].

How to revert, in concept. Put the original region code back (saved in the prior dump) with the same tool, and restart the radio. If the calibration was damaged, restore from the full dump or turn to a Yaesu technical service.

In this project. SPR/SPW, region or TX limit changes and any calibration write are excluded on purpose.

juanmmmmmmm-Look4Sat-FTX1 is an experimental Look4Sat fork with "Yaesu FTX-1" as a radio model, over direct USB OTG (no PC or rigctld). ESCRIBE EN LA RADIO (VFO, mode, split and CTCSS); no REGION/LIMITES TX, CALIBRACION or FIRMWARE was found [juanmmmmmmm-Look4Sat-FTX1:README.md].

  • Model: MAIN = RX/downlink, SUB = TX/uplink [juanmmmmmmm-Look4Sat-FTX1:core/data/src/main/java/com/rtbishop/look4sat/core/data/framework/RadioTrackingService.kt].
  • Start: MAIN mode according to the downlink mode, SUB mode according to the uplink one; initial SUB frequency = TX base or middle of the uplink band; then FT1; + VS1; (SUB as the TX side).
  • Commands used: FA%09d;, FB%09d;, MD0<codigo>;/MD1<codigo>;, FT0/1;, VS0/1;, ST1/ST0;, CN10%03d; (CTCSS tone on SUB, index 000-049, standard tones only with a tolerance of 0.05 Hz) and CT11;/CT10;; a harmless FA; check after 150 ms on connection [juanmmmmmmm-Look4Sat-FTX1:core/data/src/main/java/com/rtbishop/look4sat/core/data/framework/Ftx1CatProtocol.kt] [juanmmmmmmm-Look4Sat-FTX1:core/data/src/main/java/com/rtbishop/look4sat/core/data/framework/Ftx1Controller.kt].
  • Doppler: each 1 s cycle computes the position and the radial velocity, maps the uplink base to the downlink with the linear transponder's band step and applies getUplinkFreq/getDownlinkFreq; the user's downlink offset is applied before the mapping for the uplink and after it for the downlink; linear transponders only [juanmmmmmmm-Look4Sat-FTX1:core/domain/src/main/java/com/rtbishop/look4sat/core/domain/utility/DopplerFrequencyCalculator.kt].
  • Manual tuning: it reads FB/FA, compares with the last value sent (20 Hz threshold) and after two stable reads recomputes the TX base and resumes corrections.
  • FM: CTCSS only on SUB's uplink encoder, configurable; tracking does not apply a chosen tone by itself.
  • PTT: the software never sends it (pttOn() logs and returns false); DTR/RTS forced to false; only the microphone's physical PTT.
  • stopTracking() only cancels the task: it does not restore the previous frequency, mode, split, VFO or CTCSS.
