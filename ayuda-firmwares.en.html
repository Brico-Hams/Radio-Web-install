What “supported” means

There are four different concepts:

  1. Supported by the firmware project: upstream maintains an image.
  2. Recognized by the connector: this website knows an identification structure.
  3. Published in the catalog: a filename from an authorized source is recognized. This does not mean this website can install it.
  4. Tested on a radio: requires physical evidence for the exact model and build. Automated tests for this website are not that certification.

A row in a table does not authorize use of firmware from another revision. “Download” does not mean “flash”; “verified file” does not mean “digitally signed.”

“All versions” is documented as a matrix of families, differences, and sources by version; it is not a promise that every menu exists starting with the first firmware. For a specific build, note model, revision, date, filename, commit if available, and hash. Check its manual and release notes. Anything unconfirmed is marked as such rather than inventing values, shortcuts, or maps.

Safety and legal-use rule

  • Identify the actual hardware, not just the casing.
  • Preserve the original calibration and codeplug before migrating.
  • Do not erase, restore, or reset in response to a port error without first understanding the cause.
  • On OpenGD77, this website keeps writing blocked because it cannot obtain a verified complete MCU firmware backup.
  • On Quansheng, mutations require a full backup; Main is protected.
  • Data imported for listening starts RX-only.
  • Do not enable automatic TX or transmit outside authorized frequencies. A firmware PMR/GMRS/FRS/MURS profile does not certify a radio.

Licenses: separate components

The user's statement “the license is MIT” is recorded as pending association with the original component, rights holder, and license text. This does not change third-party or existing repository licenses:

  • The website declares GPL-3.0-or-later in its manifest and LICENSE file.
  • Inspected F4HWN sources include Apache-2.0 and NOTICE.
  • CHIRP drivers in the Karina package contain GPL notices.
  • The exact Karina firmware license does not appear in the inspected package. The user's MIT statement provides no sources and does not establish which files/versions it applies to. The corresponding notice will be included when there is a verifiable reference.
  • OpenGD77 and its components are governed by their own notices; do not assume MIT.

Complete manuals, Karina firmware, another party's calibrations, and third- party software are not redistributed simply because they are cited.

Updating this library

Value tables are generated from pinned catalogs, not memory:

npm run build:help

When a catalog changes, review the meaning of new options, versions, and dependencies, regenerate the pages, and run the help tests. The radio is not queried and its configuration is not changed when opening a guide.

The historical snapshot is in f4hwn-history-presets.json: it stores the commit, SHA-256, and CMakePresets.json content for each version. Updating it must be explicit, using node scripts/fetch-help-presets.cjs from the repository root; it makes public queries to GitHub, does not access radios or upload local files. The normal help generator works offline and does not download sources.
