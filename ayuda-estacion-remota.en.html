Integrated remote station

The original BricoHam Remote Station development is incorporated as remote-station/ into Bricohams Radio Workspace / RadiCodex. The component's own code, tests, documents, and mobile projects are kept intact, without caches, local SDKs, secrets, or build binaries. The root GPL-3.0-or-later license and the component's MIT notices are preserved; the licenses of dependencies and third-party assets are not changed.

When to use each remote implementation

The project contains two independent remote stations:

Name in the interfaceCodeUse when
Remote station (Python host/agent)remote-station/, station.htmlYou need a coordinating HTTPS host, headless Python agents, and web/Android/iOS clients. The Android client only connects.
Remote shack (rigctld, desktop)remote-agent.cjs, remote-station.cjs, remote-relay.cjs, remoto.html (README: «Remote shack»)You want to control a radio through Hamlib rigctld from the desktop/Raspberry Pi app, with its own relay, Opus audio, and the FTX-1 tuner.

They do not share ports or configuration (the second one uses ~/.radicodex/). The radio catalogs and the FTX-1 CAT parsing are duplicated on purpose: they have not been unified because the formats differ. The TX protections (TX disabled by default, high-SWR protection, ATAS/tuning time limits, emergency stop, and PTT watchdogs) are kept in both.

Integration and limits

  • The web navigation links Remote station (Python host/agent) only once. It prepares a validated HTTPS URL and opens the client served by the host; it does not collect or send tokens. The Remote shack (rigctld, desktop) entry appears only on the desktop.
  • RadiCodex Android includes an internal HTTPS screen: no native JavaScript bridges, file access, or mixed content. It pins the selected origin, rejects invalid certificates, and requests permission only for the microphone. When moved to the background it destroys the page/session, with no automatic reconnection.
  • The dedicated Android client and the iPhone/iPad project remain in remote-station/apps/web-console/, with official BricoHams branding, colors, typography, and assets. iOS requires a Mac/Xcode to build and sign.
  • The coordinating host and the headless agents run separately. The independent USB Android agent has its own APK, an outbound WSS link, and read-only FTX-1 CAT, with explicit selection and ES/EN/FR/PT diagnostics. Its physical OTG acceptance, audio, PTT, CW, digital modes, and accessories are still pending; it is not confused with the client, and those functions are not presented as implemented. The local Node firmware server is not published on the Internet nor turned into a remote proxy. No copies/codeplugs or providers are exposed.
  • The existing USB connectors, memory, firmware, and native functions are not changed. The station CAT profiles are independent and opt-in.
  • Protocol identifiers, BRICOHAM_* variables, Python packages, and application IDs are kept to avoid breaking existing configuration/clients. The aliases bricohams-station-host and bricohams-station-agent are added.

Build and run

At the root, with Node 22 and Python 3.12 or later:

npm ci
npm --prefix remote-station/apps/web-console ci
npm run build:station-branding
py -3.12 -m venv remote-station\.venv
remote-station\.venv\Scripts\python.exe -m pip install .\remote-station
npm run build:station

The host and agent packages are generated in remote-station/dist/ (a local folder, ignored by git: the artifacts are not versioned). On POSIX, use python3 and remote-station/.venv/bin/python. The secure deployment guide describes TLS/CA/hostname, optional mTLS, and secrets separated by role/link. The multilingual help is integrated into the HTTPS client and the dedicated clients.

The connection URL contains no tokens, paths, or parameters. It must point to the HTTPS host that serves the built console, not to the agent port. For RadiCodex WebView, a certificate chain trusted by Android is required; a TLS error is never bypassed. The dedicated Capacitor client requires the exact origins documented on the host.

RF validation and safety

CAT, audio, PTT, rotators, power, and ATU keep their documented interlocks and states. PTT requires opt-in and independent limits; losing the client triggers the watchdog, which does not guarantee a physical stop. Check RX on the radio. USB/RF/mobile acceptance or full compatibility is not claimed just because a profile exists. Active remote CW, active WSJT-X, native FTX-1 scope, and headless Android OTG agent are still pending; they are not simulated as real functions.

Station accessories

The station accessories layer supervises external tuners and amplifiers in the Node shack and in the Python agent (GET/POST /api/v1/accessories). The amplifier starts in STANDBY and returns to STANDBY on disconnect, high SWR, fault, lost lease, band change, or emergency stop. Tuning starts only on explicit request, at 10 W or less and time-limited. Devices without a protocol source (for example PGXL) are listed as pendiente de fuente.

Diagnostics

All components have minimized technical logging and options to send it with consent. See diagnostics and privacy for the closed contract, HTTPS receiver, roles, retention, and differences between clients.

Shared Android native library

android/station-core contains the minimized logging and the HTTPS validator previously coupled to RadiCodex. It keeps the public Kotlin package so as not to alter existing calls or screens; it receives component/version explicitly, validates both against the contract, and rejects identity changes within the same application. Stored reports from another component or version are not re-enveloped as its own. The generated contract is incorporated as a library asset into each consuming APK. Sending remains disabled by default and credentials stay only in memory. It is not yet an executable Android OTG agent: USB, service, and link to the host are still pending. The RadiCodex APK keeps its identity and existing HTTPS client. The library tests and the RadiCodex connection/diagnostics tests pass, along with both lints and the APK build. The 53 generated resources, the debug v2 signature, and the JSON contract inside the updated APK are verified. The security review limited to this extraction finds no confirmed vulnerabilities; it does not certify the complete product.

Upstream sources and first FTX-1 USB check

Public GitLab sources and links to maintained Hamlib were reviewed, without accessing private/paid Patreon or running downloaded code. Patreon provided no verifiable content; the GitLab search is bounded, not a complete inventory. The Yaesu bugs, Xiegu risks, and OpenGD77 restrictions document evidence, licenses, candidates, and limits without copying code/tables. FTX-1 now requires ID0840 before and after frequency/mode/power adjustments; a wrong model or lost identity prevents confirming the adjustment, with no retry. 230 Python tests pass, along with Ruff and verification of the 53 generated resources.

The real USB check resolved a missing driver with an official signed package and verified 15 queries over the Enhanced interface at 38400/8N1, with no setters or TX. IF returns P10=3, undocumented in 2508-C: it is rejected and PTT stays blocked when it cannot verify a safe state. RF acceptance, audio, reconnection, firmware, or the complete product is not claimed. The updated wheel and ZIPAPP were verified outside the source tree: they reject an ID from another model without setters and read ID0840 on the real USB unit. The shared bundle remains identical in the wheel and dedicated APK; the four SHA256 values match. The security review scoped to the FTX-1 identity guard found no confirmed vulnerabilities; it is not a global certification.

Operational desktop

The shared web/Android/iPhone/iPad client presents the agent controls before catalogs and protocol references. The CAT/PTT/rotator/power/ logbook links scroll the page; they do not issue commands or change permissions or sessions. The coordinator card does not authorize TX and the demo remains identified. The components keep their keys, handlers, and shutdown mechanisms.

The comparative UX study documents public sources, original decisions, and limits. It is not a copy of commercial products, a user ranking, or a visual/hardware acceptance. The main controls have a minimum of 44 px; touch and visual checks remain pending. This step does not finish the redesign of all the native Workspace screens. The portal organizes radio/agent, host, and operation in three steps, with no network or credential storage. In RadiCodex, the configuration collapses during the connection without recreating the WebView; disconnection and status remain visible. When disconnecting or moving to the background, the configuration returns, without reconnecting.

Yaesu, OpenGD77, and new candidates expansion

  • The seven Yaesu radios in the catalog have documented read-only CW queries. FT-710, FT-991A, FTDX10, FTDX101D/MP, and FTDX3000 incorporate opt-in adjustments of frequency, mode, and power setpoint per model. Correct ID, RX, tuner not busy, local limit, deduplication, and readback are verified without enabling TX. FTDX101MP supports a setpoint of up to 200 W; the other six do not inherit that limit. FT-991A and FTDX3000 do not invent MD1: secondary mode null and control disabled. Manuals, pages, and restrictions.
  • 13 experimental profiles of OpenGD77 USB CPS identification are integrated into the headless agent and the shared console. INFO only, without entering/leaving CPS, writing memory, transmitting, or inferring RF CAT. Unknown firmware/models are rejected; old builds without R9 are not presented as compatible. The original local programming/screen of the Workspace is kept.
  • Researched Xiegu and Lab599 are added as candidates without transport: the pending addresses, framing, and response details are not guessed from Icom, Kenwood, or Hamlib. The catalog contains 68 candidates, not 68 certified radios.
  • FlexRadio SmartSDR: client smartsdr_protocol.py / smartsdr-core.cjs (discovery, TCP 4992 session, VITA-49 meters, guarded TX that is off by default). VITA-49 panadapter and waterfall: pending source.
  • Final verification: 223 Python tests, 66 client tests, and 44 focused Node tests pass; Ruff, lint, and build are correct. A transient WinError 10053 abort in a rotator test was repeated in isolation and the later full suite passed, without changing the controller or the HTTP limits.
  • The updated ZIPAPP and wheel were run outside the source tree; the two debug APKs verify the v2 signature. SHA256SUMS matches the four packages. The current bundle matches byte for byte across the wheel, dedicated APK, and Android/iOS assets. RadiCodex keeps its APK: it loads the current interface from the HTTPS host, and does not incorporate a new CAT engine in the WebView.
  • Publication remains blocked: HTTPS has no credentials and SSH rejects publickey authentication. The official github.com key was verified in an isolated file, without modifying SSH profiles or disabling host checking.

These increments do not finish active CW, active WSJT-X/CAT broker, independent USB OTG Android agent, iOS/production signing, or cross-platform physical acceptance.

Languages of the operational controls

Frequency/mode and power/tuner use the ES/EN/FR/PT selector of the shared client, including errors and safety warnings. Changing language keeps readings, edited values, limits, and permissions; it does not remount controls or issue CAT requests. The linked technical references keep their original language.

Verification: 72 client tests, lint, and TypeScript/Vite pass; six new cases check language changes with SUB without mode and the 200 W limit of FTDX101MP, without altering restrictions. Wheel reinstalled outside the source tree and dedicated APK rebuilt with lint and debug v2 signature verified. The bundle matches by SHA256 in the wheel, APK, and Android/iOS assets; SHA256SUMS is updated for the two affected packages. ZIPAPP and the RadiCodex APK do not change. iOS build, physical acceptance, or production signing is not claimed.

Limited WSJT-X commands

The agent and the host incorporate an authenticated POST for Replay and Halt Tx, exclusively with local --enable-wsjtx-safe-commands. The shared web/Android/iPhone/iPad console offers both actions in ES/EN/FR/PT. There is no TX start, Reply, Free Text, or Configure; the CAT broker and full digital operation remain pending. See activation and UDP limits.

The station devices (Digital Loggers and Waveshare Modbus relays, DCU-1/Rotor-EZ/RT-21 rotors) are driven with confirmation, never switch the radio/amplifier while transmitting, and always allow stop. Signal paths and gear without a public protocol: "pendiente de fuente".

The first loopback Heartbeat/Status origin is pinned until the agent restarts. A different origin, an expired/closed instance, unsupported fields, and repeated IDs are rejected; Replay has a limit of one request per second. This does not authenticate the WSJT-X process. Delivery always declares sent_unconfirmed and does not confirm an RF stop; the UI requires a new query after an error, with no retries. Keep physical protections and check RX.

Verification: 228 Python tests and 74 client tests pass, including POST over two validated TLS links, CORS, and rejection of a response claiming to confirm an RF stop. Ruff, lint, TypeScript/Vite, and 53 generated resources are correct. A Workspace diagnostics timeout in the concurrent run was repeated in isolation and then in the full suite with two workers; both passed without changing that test or its limits.

Wheel and ZIPAPP run outside the source tree; dedicated APK with build, lint, and debug v2 signature correct. Bundle identical in wheel/APK/Android/iOS assets and SHA256SUMS updated. Security review limited to this increment and its authentication/TLS helpers: no confirmed vulnerabilities. It does not certify the whole product, WSJT-X in real operation, or hardware.

Remote menu settings

The shared model (radio-settings.cjs, data/radio-settings-catalog.json) lists, per radio, each setting with id, type, range, read/write command and source. The Node agent exposes GET /api/settings, GET /api/settings/value?id= and POST /api/settings; only the FTX-1 has a sourced EX menu map (ftx1-menu.js). Every write requires the operator role, reads the current value as a backup, validates the range, writes, reads back and compares, and restores the backup on mismatch. It is refused during TX, one write at a time, rate limited and audit logged. Calibration, reset, region/TX limits, CAT speed/stop bits/timeout and USB ports are never written. Anything without a source is shown as "pendiente de fuente" and read-only; codeplug-only radios point to the desktop editor. Never transmit without a matched load or antenna.

The Python agent (remote-station/bricoham_station_agent/menu_settings.py) exposes the same model for the FTX-1 through POST /api/v1/radio-settings (menu_list, menu_read, menu_write); writing requires menu_write_enabled: true in --radio-settings-config (off by default) and the React panel shows it. "MAX POWER", REGION/TX LIMITS, CALIBRATION, reset, CAT, USB/TUN-LIN, AUTO POWER OFF and TX timer items are read-only; a ?; reply means "not available", not a value. The real bench replies (EX0104133;, EX030503100;, EX050109; -> ?;) are test fixtures. IC-705: the Android app (Rig screen, USB CI-V, button "Radio settings (CI-V)") reads and edits the 1A 05 <sub> settings of the IC-705 CI-V Reference Guide rev. 6 (printed pp.2 and 5-8; the guide itself is local and never versioned) through the same safe write (RigSettings.kt, table checked against data/radio-settings-catalog.json). TX time-out, PTT lock, tuner PTT start, SEND/keying outputs, max TX power, band-edge beep, auto power OFF, CI-V/USB link items and REF adjust are read-only; the composite items 0001 and 0046 are pendiente de fuente. The Node and Python agents list the IC-705 model read-only because no sourced raw CI-V route exists there. The Android web consoles reuse the Settings tab of the Node agent.

Extended remote operation

The Node agent (remote-agent.cjs + remote-ops.cjs) adds guests with their own token and per-radio permissions (bands and maximum power enforced in the agent), a TX log with CSV export, remote power-off only where sourced (FTX-1 PS0, with confirmation), optional public listening (off by default), signed update notifications (never installs without consent) and an installable PWA. Never transmit without a matched load or antenna.

Languages without interrupting active controls

PTT, rotator, RX audio, and the CAT/WSJT-X panel share ES/EN/FR/PT, including safety warnings and local framing errors. The stop and renewal callbacks keep their identity when changing language; the lease is not restarted, START/MOVE/STOP is not sent, and the audio graph is not recreated because of that change. The agent's technical responses and external errors keep their format/language.

89 client tests, lint, and TypeScript/Vite pass. The new cases check active PTT/rotator with renewal and subsequent stop, no new commands when changing language, preservation of AudioContext/node/request, translatable framing errors without reopening audio, and preserved CAT selection. The prepared TX microphone also keeps its instance and session when changing language; losing focus still closes it and requests RX. The initial check detected deferred visual translation in the helper; translation and rendering were separated and the callback made stable before validating the full suite. Wheel reinstalled outside the source tree and dedicated APK rebuilt with lint and debug v2 signature checked. The same bundle appears in wheel/APK/Android/iOS and SHA256SUMS matches the four packages. ZIPAPP and the RadiCodex APK do not change. Physical/mobile acceptance or iOS build/signing is not claimed.

Normalized meters and tune check

remote-meters.cjs + data/remote-meter-model.json are the single meter model (S, PO, SWR, ALC, COMP, ID, VDD) for the Node shack, the React console (meterModel.ts), Android (MeterModel.kt) and Python (ftx1_cat.py). FTX-1 scales are cited from the CAT manual 2508-C (RM/SM) and bg7nzl-ftx1ctl; they are uncalibrated estimates. PO is only scaled with the field head (PC1); with the SPA-1 (PC2) it stays "pendiente de fuente". Temperature has no source.

Tune (internal AC 20 s, ATAS 45 s) uses a state machine: operator request, readback confirmation, time-capped wait, final SWR and TX0 verified by readback. The result (success/fail/timeout/unverified) is shown in the console. On ATAS, if the radio did not indicate that the tuner worked (evidence(false)) and SWR is not high, the result is unverified (reason no-tune-evidence, text “Tune unverified”), never a success. If TX0 is not confirmed by readback the result becomes a failure (tx-stuck). bricoham_remote_station/tune_check.py is the Python mirror of TuneCheck; today only its test (test_tune_check.py) exercises it. It is refused if the configured power exceeds 10 W (TUNE_POWER_MAX_W): the operator must lower it; it is never lowered automatically. Hamlib G TUNE is also time-capped. Never transmit without a matched load or a connected antenna. Tests of this extension were not run in this environment.

TX safety of the Remote shack (Node)

Layer documented in ARCHITECTURE.md and MAPA-TECNICO-PROYECTO.md. The software never transmits by itself; PTT off pre-empts any other action.

  • Out of band (remote-txsafety.cjs, txRanges in ~/.radicodex/remote-agent.json, a list of { startHz, endHz }): the occupied spectrum (occupiedSpan, the radio's bandwidth or a default one depending on the mode) must fall inside a range. Without configured ranges it does not act (not-configured). An unknown frequency or mode rejects a new switch to TX (HTTP 409, tx-range-unknown/tx-out-of-band); leaving the band cuts an agent transmission. During a tune the mode reported by the radio is not evaluated. The Python agent has its equivalent in bricoham_station_agent/txsafety.py (tx_ranges, used by ptt.py).
  • Orphan TX: OrphanWatch releases an agent transmission without a lease holder after two consecutive observations, in addition to the heartbeat (1 s) and the TX and tune caps.
  • VOX (remote-vox.js): armed only by an explicit action in the session, uses the same PTT, heartbeat, and lease path as the button, and disarms on rejection, drop, loss of control or link, lock, or hidden page. It is not saved. Threshold and delay are bounded (0.02-0.5 and 250-2000 ms).
  • Speech processor (remote-speech-proc.js, txProcessing.ts in the React console): off by default, bounded settings, and a fixed −1 dBFS ceiling; settings are saved only as a local preference.
  • Amplifiers (station-amplifier-drivers.cjs, mirror amplifier_drivers.py): KPA, Expert, ACOM, and Gemini implemented from source and not tested on hardware. They never transmit or power the equipment off; each step to STANDBY is read back and, if unconfirmed, OPERATE stays blocked.
  • Agent close: close() waits (cap stopStepMs * 5 + 500 ms) for an in-flight stop and repeats the full stop sequence once before releasing rigctld.

Software guards do not replace physical interlocks. Always check RX on the radio.

Remote waterfall of the received signal

spectrum-core.js (Node remote shack UI, and so the Android WebView) and spectrum.ts (React web console, and so the Android remote station client) compute an FFT of the RX audio that already arrives over the authenticated /api/audio or /api/v1/audio channel; no second audio listener is opened and no new network traffic exists. They draw at most 25 rows/s on a fixed 640 px canvas, with dB scale, colour map, pause and adjustable range. The radio's native scope is used only where a source exists: drivers/icom_scope.py and SpectrumCore.createScopeAssembler implement the 27 00 frame per third_party/ftx1/rigplane-rigplane-core/docs/api/scope.md (MIT, which cites the IC-705/7300/7610/9700 CI-V guides), and SerialCat.scope_stream (Python agent) reads it live only on IC-705, IC-7300, IC-7300MK2, IC-7610, IC-905 and IC-9700 (the six with 27 00/27 10/27 11 in the rigplane profiles; IC-705 CI-V guide pp. 27-28; main receiver only): it enables the scope with 27 10 01 and the output with 27 11 01, reassembles 27 00 at up to 10 frames/s for at most 30 s and always disables it with 27 11 00 (commands from commands/scope.py, scope_data_output; receive only, never PTT) and serves it on GET /api/v1/cat/scope?seconds=&fps= (NDJSON, authenticated). The Node agent talks to rigctld, which delivers no unsolicited frames: it stays "pending a source" there and uses the audio waterfall. Clicking the waterfall tunes only in USB/LSB/PKTUSB/PKTLSB through the existing frequency path (RF = dial ± tone); there is no new TX path. Do not transmit without an antenna or matched load.
