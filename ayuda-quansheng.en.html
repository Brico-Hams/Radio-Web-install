Quansheng: F4HWN, versions and configuration

Revision: 26-10-2026. Inspected functional baseline: Fusion61, commit f556a96e73c3e423a00cf473aeb37f827cac05a5; modular web catalog v6.3.0, commit ca3a4271386049e7b459b215cef0ad0eea1a30ca. This guide does not automatically attribute v6.1/v6.3 features to v4 or v5. For how the radio works internally (pins, memories, protocol, bootloader, schematics, and photos), see UV-K5 V3 technical atlas.

Live viewer and RF log

In Channels, the two tables appear side by side on desktop and stacked on mobile. Select the compatible model and authorize reading in Backups and connection. Return to Channels and click Connect and read channels (read-only): the left column shows the active bank without write permission. On the right, choose PMR446, REMER VHF, or Bricohams Murcia repeaters and click Prepare template for dragging. Channels prepared from CSV and other catalogs appear here too. Drag a row or selection to the left, or use Copy selection and Paste here. Catalog channels are inserted RX only using an existing FM memory as a template; AM and DMR are not converted. Dragging changes only the local copy. Save it before rereading: replacing it requires confirmation. Physical writes still require a complete Flash backup, confirmation, and rereading. The new channel connection does not start the viewer automatically, so it does not occupy the port during reading.

Physical test on 2026-10-27: USB serial device COM4, identified firmware F4HWN v6.1.0, 41344-byte active bank with 121 FM channels. Two complete reads matched byte for byte (SHA-256 16f9c8b5ccb9d865ceaca599acf1766737641d8e8285a832680c2f745b02a331). The published web app displayed all 121 channels and prepared 16 PMR446 channels; inserting PMR01 produced 122 channels only in the local copy, with writing disabled. Only identification and read commands were sent: no writing, reboot, or bank change. This does not validate physical writing or the APK on a phone.

The viewer appears at the top of the Quansheng section. It starts when the connection completes: immediately with Connect read-only / CAT, or after the backup with Connect and back up. It requires an image with K5Viewer enabled and no lock that prevents the protocol. If no frames arrive within ten seconds, it reports this and stops; it does not simulate the screen.

  • Real 128 x 64 LCD, PNG capture, and firmware-reported LED status.
  • One connection and one reader. Any operation first pauses the viewer, lets frames finish, and then runs the command. Start viewer and RF log resumes it. Pause viewer retains the last capture.
  • The RF log appears at the end. It receives RF Log v2 and firmware history, removes duplicate sequence numbers, and retains up to 512 entries in RAM. RF Log must be enabled: no data does not mean no signals.
  • Export RF log CSV downloads the sequence, RX/TX/power-on event, frequency, duration, memory number/name, raw meter value, and battery. No UTC date is assigned to records that do not include one. Meter values are not calibrated power measurements. The CSV neutralizes spreadsheet formulas.
  • Reconnecting clears the previous view to avoid mixing radios. Export first. Stopping the viewer does not erase the radio's persistent log.

Protocol reference: UV Studio, revision e7aa946f6de002559e1aaf3f91765db7fc2ed567, k5viewer.js, and rf-log.js. The local implementation does not send PTT, keypresses, reboot, or persistent commands. The COM4 test on 26-10-2026 received 24 LCD frames and one RF frame from firmware that remained running, with no incomplete data. USB DTR had to be enabled; Web Serial explicitly sets it for Quansheng. The radio did not send stored RF entries, so no physical validation is claimed for a history that was not received. The history parser, mutual exclusion, web screen, and CSV were also checked with test frames. K5Viewer must be enabled in the active firmware.

Precompiled catalog without build tools

The website includes nine v6.1.0 images: Bricohams ARDF, Satellite, Spectrum, Labs, and Fusion, plus the official F4HWN Fusion, FieldOps, Transfer, and Labs. No folder selection is required. The same catalog is used on the local server and in the static export. It is not a dynamic download from an arbitrary URL.

  1. Select UV-K1 or UV-K5 V3 and an image from the catalog.
  2. Confirm the model and Beta status of Bricohams derivatives.
  3. Download, verify, and prepare for slot checks size, SHA-256, and PY32 structure before enabling the image. Download BIN and manifest lets you save it without preparing or writing it.
  4. Select slot 1-4, a name, and Install and verify CRC. Backup protections remain in effect; Main, CFG, and calibration are not erased.
  5. Manually boot each slot and check SysInf and its functions.

Bricohams images remain Beta without complete boot validation, even when their Flash write has been verified by CRC. The catalog retains original metadata: a structural test is not converted into hardware certification. The official release catalog remains available for other versions; variants incompatible with slots are download-only.

Maintenance: npm run publish:firmware verifies the five local builds pinned by SHA-256 and retrieves the official v6.1.0 release with GitHub hashes. It writes the catalog only after validating every file. The Bricohams GPL and upstream Apache licenses and notices are distributed. Options, integrated-source hashes, and upstream commit are listed in each precompiled/catalog.json entry; the builder and source modules are in this repository. User configurations and calibrations are not included in the catalog.

Advanced options and restoration scope

The Bricohams custom tools panel contains internal access to the keyboard/reboot, main firmware DFU v6/v7, calibration backup/restore, logo download/installation, Flash backup/restore, app catalog/order/erase, slots, and RF filters/export. It does not open UV Studio, load its scripts, or delegate these operations to another website. Binary provenance and license links are retained; they are not runtime dependencies of the interface. Stock restoration rebuilds external Flash and requires the DFU step, with different images for UV-K1/UV-K5 V3, preserving the unit's own calibration. Do not confuse this with Reset CFG bank, which erases only one bank.

Native maintenance and factory/DFU panels implement the published protocol independently, without copying UV Studio's interface or code. Versions are not fully at parity: slots and channels retain their v6 workflow; DFU accepts v6 BIN and v7 FWAT/FWA1 packages. V7 resources are installed only in the active firmware with a matching Build ID and a new backup. All v7 support was tested in simulation, not on this physical radio. Pause the viewer before starting CAT tracking: they share the port. CAT and the viewer remain blocked while a factory recovery is pending.

Main firmware / custom DFU: select an F4HWN v6.x PY32 BIN from 256 bytes to 118 KiB, or a v7 package with an FWAT trailer and FWA1 resources. The package is split locally; only the internal image is sent to DFU. Package limits, exact lengths, package CRC, and resource CRCs are checked. V7 without the complete package and unknown versions are rejected. The image is checked for vectors, version, and SHA-256, but this does not guarantee provenance or physical compatibility. A full backup and the phrase FIRMWARE PRINCIPAL UV-K5-V3 or FIRMWARE PRINCIPAL UV-K1 are required. Preparing does not write; it stores an immutable in-memory copy, blocks other operations, and enables the DFU button. Disconnect here, manually enter DFU with PTT, and confirm DFU PRINCIPAL UV-K5-V3 or DFU PRINCIPAL UV-K1. Do not close the page or switch radios between steps.

This flow replaces internal firmware, not the bootloader; it does not erase external Flash or synchronize the multiboot external Main image. The multiboot selector may restore another image at boot: check slots and verify manually. Rollback is not guaranteed. The bootloader, consistent identification, page number, and status of each ACK are checked. DFU has no readback: completing pages does not validate boot or RF. If it fails, keep the page, backup, and same radio for retry. Simulation-tested only.

V7 external resources: after DFU, boot v7 normally and connect with a new full backup (if that cannot be completed, writing remains blocked). The screen may be blank while resources are missing. Select the same complete package or its FWA1 in V7 external resources. Check the file without writing, then confirm RECURSOS UV-K5-V3 or RECURSOS UV-K1 to install. The active slot and Build ID are queried using 0x0750; a different Build ID stops the process before erasure.

Only the active slot's resource area is erased using 0x0752; blocks of up to 128 bytes are written with 0x0754, and the 32-byte FWA1 header is written last. Only an identical block is retried on timeout (up to four retries), never erasures or rejections. 0x0756 validates resources, and the final query must report the same slot/Build ID, valid status, and loaded resources. Erasing revokes write permission after any attempt: reconnect and back up again. No physical readback is offered for an area whose address is not published here; the result is firmware validation, not proof of display or boot. An interruption can leave resources incomplete: keep the package and backup for recovery. Resources are not installed into inactive slots, and the v6 map is not used for v7.

Custom RF log: filter by memory name, MHz frequency, and RX/TX/power-on event. Filters change only the view; they never delete received history. Export the selection as CSV or the full log as JSON bricohams-rf-log v1. exportedAt is the export time, not the event time; eventUTCProvided and calibratedRF are false. UTC dates, calibrated RSSI, and spectrum analysis are not invented from the history.

Authorship and rights: these tools are Bricohams' own implementation, but third-party firmware, apps, and resources retain their licenses and attributions. Rewriting the website does not make those files original work or guarantee freedom from claims. Apache/GPL notices are not removed, and stock images are not redistributed inside the website.

Native remote keyboard: in the viewer, it requires a full backup of the current connection, manual enablement, and confirmation for every key. It offers digits, MENU, up/down, EXIT, asterisk, hash, and F1/F2, with short or long presses; it has no PTT or global shortcuts. Keys may change settings, and F1/F2 may trigger transmission features according to their assignments. Do not assume receive-only operation. Each send disables the keyboard again. Only UART transmission is reported; no execution ACK is fabricated. Check the LCD. It is locked when paused, permission/connection is lost, CAT starts, or factory recovery begins.

Native reboot: requires a full backup and entering REINICIAR RADIO, even in advanced mode. It pauses the viewer, sends one 0x05DD command, revokes permissions, and closes the connection. It does not retry or claim an ACK or successful reboot; check the radio and reconnect for a new backup. It does not change the slot or CFG bank and may lose transient state. Keyboard and reboot were tested in simulation, not on the physical radio.

Native maintenance: allows downloading/installing an ST7565 BIN or exact 128 x 64 PNG logo, exporting/restoring the 512 calibration bytes, and exporting/restoring 2 MiB of external Flash. Writes require a full backup of the current connection and explicit confirmation. The logo is read back and neighboring data checked. Flash restore preserves the entire current calibration sector, skips identical sectors, and writes multiboot status sectors last. Both Backup and Restore verify all 512 4 KiB sectors using the firmware's physical CRC: command 0x073E cannot query 2 MiB at once. The stored global CRC is calculated locally over the image whose sectors have already been compared. Restoring calibration or Flash revokes write permission: reconnect. Do not import calibration from another radio.

Native factory restore, irreversible: this is not CFG reset. Select the exact model and download the two stock BIN files from the wizard links. Size and SHA-256 are checked against the pinned official revision e7aa946f6de002559e1aaf3f91765db7fc2ed567; these BIN files are not redistributed.

  1. Export the full backup outside the browser and verify both BIN files.
  2. With the same radio connected normally, confirm FABRICA UV-K5-V3 or FABRICA UV-K1. Step 1 replaces slots, every channel bank, apps, and logs, but preserves the entire calibration sector.
  3. Wait for the full Flash verification. Do not close or reload the page: step 2 authorization exists only in memory. Do not boot normally before both steps are complete, and do not switch radios.
  4. Click Disconnect; turn off the radio and hold PTT while powering on for DFU (LED on, screen off). Release PTT, select step 2, and confirm DFU UV-K5-V3 or DFU UV-K1.
  5. The wizard verifies the bootloader and confirmation of each page. It accepts only bootloader 7.00.07 for V3, and 7.02.02 or 7.03.xx for K1. Retries are limited to the same page on timeout, never rejections. DFU has no readback: confirmed pages do not prove boot.
  6. Boot manually and check version, reception, and operation. If step 2 fails, keep the page and retry it with the same image. If step 1 fails, do not attempt DFU or boot normally: keep the backup, disconnect here, and use official recovery.

Maintenance and DFU were tested with simulated devices. The four official stock files were downloaded and validated with the production verifier. No factory restore, calibration, logo, or full Flash restoration was performed on the physical radio during these tests.

Phase 4 step by step: flash the main firmware

  1. Save the Phase 2 backups. Do not continue without saved calibration.
  2. Close CHIRP, CPS, other Studio tabs, and this website's normal connection.
  3. Turn off the radio. Hold PTT while powering on: the LED stays on and the display stays off. Release PTT and connect the USB-C cable.
  4. In UV Studio or Bricohams Studio, select the port. The bootloader must report 7.00.07 (UV-K5 V3) or 7.02.02/7.03.0x (UV-K1). For any other version, stop and check the model.
  5. Choose the plain .bin for the edition. Never use a *.packed.bin (for the official updater) or a V1 image.
  6. Confirm and do not touch the radio or cable until every page is confirmed. If interrupted, the radio remains in update mode: repeat from step 3 with the same file.
  7. The radio restarts on its own. After flashing F4HWN, save calibration again with UV Studio, as the project recommends.

Phase 5: first boot

  • Open SysInf and note the version and edition. If they do not match the file, do not continue: repeat Phase 4.
  • Flashing does not erase calibration. If the battery reads 0 V or squelch behaves unexpectedly, confirm the calibration belongs to this radio before changing anything.
  • If menus show inconsistent values after a firmware change, use Reset only after checking your backups: its scope depends on the build.

Prepare and send FM memories

  1. Select UV-K5 V3 or UV-K1 for the device and confirm the model. To read without waiting for a full Flash backup, use Connect read-only / CAT. This session does not create a backup or enable persistent writes. A normal connection retains the automatic backup required for writing.
  2. Click Read channels from active bank. In v6.0 they appear automatically from the partial copy; after a full backup, the active configuration is also read. To work without a radio, open an F4HWN v6 logical configuration that is exactly 41344 bytes—not firmware or a full Flash image.
  3. Prepare analog PMR446 channels 1-16 (RX only), FM repeaters, or SAT/Doppler memories in the planner. Select an existing FM memory as a template and click Add channels to the open local file. The first FM template is selected when the file is opened and retained when the table is refreshed. A configuration with no FM memories needs a valid template from its own firmware; arbitrary records are not generated. You can also import FM channels from CHIRP CSV or OpenGD77 CPS; only supported VHF/UHF frequencies are accepted, and DMR/other-format rows are excluded with a reason. The repeater-file field accepts those same CSV files and sends them directly to Prepared Channels. RepeaterBook JSON requires authorization confirmation and first goes through the selection table.
  4. New memories have TXLock enabled, tones and DTMF disabled, and Reverse disabled. PMR is prepared as narrow FM. Only nominal RX/TX frequencies from 136-174 or 400-470 MHz are imported; this does not authorize transmission. Names use the first 10 ASCII characters. Duplicates are skipped only when the equivalent existing memory already has TX locked; a match that permits TX is not considered valid.
  5. Edit changes an FM memory's name/RX/TX, and Delete from file removes that memory from the local copy. Editing enables TX lock and preserves bytes outside those fields; both operations work on an in-memory copy. Recheck the channel shown by the parser, click Save local configuration, and save the edited binary separately from the original. When Chrome/Edge offers a file picker, the website writes and closes the file before confirming. In browsers without that picker, it only requests a download: check Downloads and do not mistake the request for a confirmed save. Saving a JSON or CSV project is not a substitute for this binary.
  6. Write and read back channels (Beta) is enabled only with a full backup from this session, using Labs v6.1+ with Flash read and CRC support. It checks that the radio is unchanged since the read, writes 8-byte blocks, and reads everything back. During writing, affected memories are temporarily marked empty; they are reactivated after their data/names are written. This is not power-failure-proof transactional writing. VFO, settings, calibration, and other banks are protected.
  7. On success, manually restart the radio to reload caches. If it fails, keep the backup and exact message; do not assume success based only on an ACK.

Sending was verified with simulated transport, not on hardware: the connected v6.0 unit does not allow the required full backup. The unit is not updated or flashed as a side effect. The native SAT orbital table is not installed: SAT/Doppler are FM memories. Continuous CAT RX tracking specifically requires the Bricohams Satellites image with CAT v1.

Simulate the multiboot cycle without writing to USB

The automated regression test runs with:

node --test --test-name-pattern="simulacion multiboot completa" tests\connectors.test.cjs

It uses only an in-memory transport: it does not open Web Serial, COM, or USB. It simulates four installations using test images, a full backup and session-scoped permission, a header written last, and each slot's CRC. In the model, it manually selects CFG banks whose numbers differ from the slot number, so the two are not confused. Each bank imports 16 PMR channels, 11 REMER channels, and a fictitious repeater CSV; writes, reads back, edits, changes a list, deletes, and reuses a memory. It checks isolation between banks, Main, calibration, and protected settings. In Satellites it simulates CAT RX and STOP without persistent changes. AM is rejected because this importer does not convert it.

CSV files accept trailing decimal zeros, such as 145.600000 and offset 0.600000, without rounding values that require more than five significant decimal places. The test repeaters are not a current directory of real frequencies. This simulation does not run compiled firmware or test boot, RF, display, audio, or physical isolation of banks in the connected radio. It does not unlock writes or replace the full backup required for that unit.

Page sections and channel tables

Sidebar steps (Backups and connection, Channels, Satellites, Firmware, Tools) show only the selected section; tools-menu links open the section containing their target.

Channels has two tables: Radio channels, read from the active bank or opened file, and Channels to load, prepared by repeaters, REMER, PMR446, SAT/Doppler, airports, FM/CSV or copied from the radio. Drag a row to reorder; intermediate rows shift. Drag from the load table into the radio to insert before the target, or append in an empty area. Copying from the radio preserves every byte, including DCS. Select rows and use Copy selection / Paste here, or Ctrl+C / Ctrl+V with the table focused. Radio paste inserts before the first selected row or appends if none is selected. Only contiguous memories up to the first gap shift; later memories remain unchanged. These are local edits, not USB writes.

Channel Backup and Restore buttons

Authorized exceptional legacy firmware replacement

The advanced API BackupManager.authorizeSlotReplacement authorizes only firmware installation in slots 1-4 for F4HWN legacy with a partial backup, after the user literally accepts REEMPLAZAR SLOTS SIN RESPALDO DE FIRMWARE. This acceptance means the previous images will be lost without a recoverable copy; their CRCs are not a backup. Connecting, using PRO, or importing a file does not enable this authorization.

Before issuing authorization, the current session's calibration and configuration are read and persisted. The partial record retains the acceptance, slots, names, sizes, and exact SHA-256 hashes of the images. Each installation rechecks that record and consumes one authorization for that image and slot. This permission does not allow separately erasing slots, Main, restoring Flash, writing channels, resetting CFG, or installing/removing apps. The normal website still requires a full backup.

This path follows UV Studio's installation protocol: erase a slot, write image blocks, write the header last, and check CRC. It is not a full backup or proof of boot. If writing or verification fails, stop and do not boot that slot. Test each image manually and leave Main intact.

Back up active bank performs a fresh read and saves the 41344-byte binary with date and SHA-256. It does not download the local edit in its place or replace that edit. The result distinguishes a written file from a requested download. This is a logical copy, not a backup of Flash, firmware, or calibration.

Restore: open channel backup requires connecting and reading the destination bank first. It validates size, structure, and an identical version; copies only memories, names, and attributes through 0x8800 onto the read of the destination; preserves that destination's settings; and asks for confirmation before replacing the local edit. It can restore channels with TX enabled: review them before writing. It does not write by itself. To send, use Write and read back channels, subject to its full-backup, confirmation, and readback requirements. Flash backups and UV Studio packages are not imported.

Regional templates and preset files

In Repeaters, Prepare 3 Bricohams Murcia repeaters adds ED5YBF Carrascoy, ED5YAK, and ED5YAL Sierra Espuna, transcribed from the supplied Bricohams Studio ZIP's PRESET_CSV. The CHIRP CSV file can be downloaded without relying on external services. Receive-only throughout; the CSV uses Duplex off and lists nominal TX in comments. Current status has not been confirmed, and CTCSS is not programmed.

Murcia templates are displayed and downloaded separately:

  • LEMI, LELC, and LEAL airports plus guard frequency 121.500 MHz: 15 AM services in JSON. RF carriers and 8.33 kHz designators remain separate.   • FM Murcia: 15 Onda Regional and OR Musica entries from Where to listen, consulted on 26-10-2026. This is a broadcast selection, not every commercial station. Transmitter coordinates are not verified, and there is no proximity filter.

AM and WFM broadcast templates are for reference/export; they are not converted to communications FM. The current Quansheng memory editor does not install them; a compatible receiver and format are required. Downloads do not prove reception, activity, or hardware writes.

Scan lists by zone or geography

New memories participate in all lists by default (value 25); participation is not set to zero. You can choose one list from 1-24 for the batch, zero for no participation, or group by zone, province/region, or locality. Grouping reserves free numeric lists without replacing existing lists. If the selected field is missing or there are no free lists, the batch is rejected without changing the image. A province is not inferred from frequency, and geolocation is not used implicitly.

REMER includes its zone; RepeaterBook retains region/locality. A CSV can include additional Zone, Region/State, City, and Country columns. Without them, you can use one list for all or the CSV format's generic zone. The report shows the number assigned to each new group; record it before closing. List names, priorities, ALL/MIX, and global settings are not changed. Skipped duplicates keep their previous list.

To change existing channels, mark them in the table, choose Assign selection to list, and click Apply list to local file. You can also edit one memory's list. Assignment removes its scan-exclusion mark but preserves frequencies, tones, modes, and TX lock. Save the binary and check ScList on the radio after an authorized write. These are not DMR zones or multiple groups per channel; each memory has one native participation number.

Saved passes and CAT RX

Save pass plan as JSON preserves the TLE, position, schedule, and selected FM frequency. Reopen pass plan JSON requires consent to use the position in the file, validates the data, and recalculates schedules for the current time without querying providers. Old schedules are not used to control CAT. An expired TLE is rejected: update the elements and recalculate. Older plans without a frequency can be opened, but you must look up and select the FM frequency again.

To add a pass to the configuration, select the frequency and pass, then use Prepare channels with Doppler correction, Load prepared SAT / Doppler, and Save local configuration. Saving schedules does not install TLE data in firmware. These options do not record radio audio.

For CAT, connect in read-only mode, manually boot the correct Bricohams Satellites image, enter SAT RX, press 8, and check the firmware confirmation in the panel. Do not try CAT with original F4HWN, ARDF, or Spectrum: they do not implement the private command. Select a currently visible pass and keep the page in the foreground. RX commands expire after 3 seconds; the browser's command cadence accounts for each command's response time. Stop does not send another tuning command if SAT RX is already disabled.

Automated and browser tests check PMR, editing, lists, and export using synthetic data and the configuration read from the unit. A real USB read is not equivalent to verifying writes, display, or RF. Without a full backup and an unambiguous bank, physical writing is not declared verified, and slots or calibration are not modified.

Multiboot and independent channels by profile

The connector reads only the logical configuration presented by the booted radio. It does not select firmware slots or CFG banks, nor does it prove that the visible profile or slot corresponds to the storage that would be written. There is no website operation that distributes a channel plan to every slot.

To keep profiles separate, manually boot each profile/bank you want to manage and repeat the read and export workflow separately. Label each file with model/revision, firmware version and profile, CFG bank if verifiable on the radio, and date; also retain its SHA-256 hash. Save and close the previous file before editing another profile. Compare reads: if firmware cannot identify the slot, or two backups do not establish isolation, treat separation as unverified and do not write. Do not copy a file between profiles assuming memories are shared or remain independent.

No new USB test was performed in this session. For the previously documented unit (F4HWN v6.0.0), the available backup remains partial and physical writing is still locked. The new edit, delete, and post-import channel checks validate the local file; they do not prove that firmware displays the channels or that the change reached a physical slot. See REMER, airports, and commercial FM for the differences between local preparation, parser compatibility, and RF testing.

In v6.1, Full Watch checks VFO A, VFO B, and valid priorities. These are not four independent receivers. Labs and apps

The inspected codebase documents 16 slots and radio, APRS, SSTV, diagnostic, and demo apps. The set changes between releases; not every app is available or compatible with every build.

Precompiled Labs app catalog: includes SystemInfo, BroadcastFM, Cube3D, Tetris, Breakout, and Minesweeper from upstream release v6.1.0. They are served with the website, including the static export, without compiling. They are Apache-2.0 and retain their original authorship; they are not renamed as our work. SHA-256, size, FAP1, name, version, ABI, and minimum API are checked. All require ABI 1 and minimum API 2; confirm compatibility with active Labs. Boot has not been certified on this unit.

Select a model and app, confirm compatibility, and click Verify and prepare app. This only prepares the file: query the slots, select a destination, and separately click Install app and verify. You can also download the file and its manifest. Apps are not installed or run automatically. The test catalog excludes beacons and distress apps; the full catalog remains in UV Studio. This is not an isolation guarantee: every native app has access to the radio.

The maintainer regenerates this catalog with node scripts/publish-firmware.cjs --apps-only: only the six archived files and pinned hashes are accepted; any change is rejected.

The connector checks FAP1, code/resource limits, and resource CRCs, then reads written blocks back. Accepting a header does not prove that an app can run: ABI, API, or capabilities may reject it at load/run time. Use firmware and apps from the same release. Installing an app from an unknown source gives native code access to the radio.

Export app from slot rebuilds the FAP1 file from the header, physical code, and resources, and checks their CRCs before requesting the download. Requires firmware with physical Flash read support; this is not a catalog download.

Move app to empty slot lets you reorder apps without overwriting another. Select the source and an empty destination, then enter the displayed confirmation. The destination is installed, read back, and verified before the source is erased and checked as empty. This is not atomic: an interruption can leave two copies or an incomplete destination while the source remains intact. Keep the backup and query the slots again before retrying. To swap two occupied apps, use a third empty slot as a temporary location. This does not run an app or certify ABI/API compatibility.

Erase all apps requires a full backup and the phrase BORRAR TODAS LAS APPS, including in advanced mode. The actual slot count (16 or 48, depending on firmware) is queried; only occupied slots are erased, and all slots are checked as empty. An error stops the process without claiming overall success; a partial erase is not rolled back automatically. Channels, configuration, firmware, and calibration are untouched. These new operations were verified with a simulated radio; they were not run on the physical unit.

APRS TX requires a legally configured callsign/SSID, position, and route. Loading a .app does not make this website transmit; automatic beacons are not configured as part of a backup. Emergency/EPIRB functions are mentioned as upstream inventory only: do not test transmissions on distress frequencies.
