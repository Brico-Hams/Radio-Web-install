Connaissances Yaesu FTX-1 : référence de recherche

Introduction et légende de sécurité

Ce document rassemble ce qui a été appris de 22 dépôts publics sur le Yaesu FTX-1 (commandes CAT, USB, mémoires, firmware, matériel, satellites et architectures distantes) et le compare à ce que fait déjà Bricohams. C'est un document de référence : il ne remplace ni le manuel officiel Yaesu « CAT Operation Reference Manual » ni l'aide utilisateur docs/AYUDA-FTX1.md.

Où se trouvent les sources : chaque dépôt est cloné sans modification dans third_party/ftx1/<carpeta>. Le tableau avec l'URL, le commit et la licence de chacun se trouve dans third_party/ftx1/SOURCES.md. Les citations s'écrivent [carpeta:ruta], avec le dossier sous third_party/ftx1/. Les citations [SOURCES.md] pointent vers third_party/ftx1/SOURCES.md.

Légende de sécurité. Ces étiquettes marquent les lignes et les paragraphes :

  • ESCRIBE EN LA RADIO : enregistre des données qui persistent dans la radio (mémoire, menu, horloge, état) ou modifie l'état de la radio.
  • REGION/LIMITES TX : modifie ou affecte les bandes ou la puissance sur lesquelles la radio peut émettre.
  • CALIBRACION : touche aux données de calibration d'usine.
  • FIRMWARE : lit, prépare ou charge un firmware.

Ce projet n'automatise jamais rien de ce qui est marqué REGION/LIMITES TX, CALIBRACION ou FIRMWARE. Il n'automatise pas non plus l'émission (PTT, CW, coupleur). Tout ce qui est marqué ESCRIBE EN LA RADIO et que l'outil propose (mémoires, menu) exige de lire d'abord, de faire une sauvegarde, de simuler et de vérifier par relecture.

Notation : les commandes sont de l'ASCII terminé par ;. P1 est le côté : 0 = MAIN, 1 = SUB, sauf indication contraire. ?; est le refus de la radio. « Réglage seul » signifie qu'il n'y a ni lecture ni réponse. Le CAT exige un firmware MAIN 1.08 ou ultérieur [gnfrazier-ftxcat:Installation_and_Transceiver_Setup.md] [ew1abz-yaesu-ftx-1-memory-manipulator:doc/cat-version-diff.md]. Trois révisions du manuel CAT ont été vues : 2306, 2507(-B) et 2508-C [captobie-ftx1-remote:ftx1-cat-manual-errata.md] [ew1abz-yaesu-ftx-1-memory-manipulator:doc/cat-version-diff.md]. Le manuel 2508-C compte 89 familles de commandes dans l'index (90 avec EO, qui n'apparaît que dans le tableau de détail) et 580 lignes de détail, dont 427 pour EX [rigplane-rigplane-core:docs/validation/cat-audits/ftx1.md].

Aucun dépôt étudié ne contient de code qui grave un firmware, change la région ou les limites de TX (sauf l'outil de région de la section 5 et les menus de puissance PC/EX), ni n'écrive la calibration. Du firmware, seule la version est lue avec VE.

Outil de région et plages de TX

Résumé seulement. ESCRIBE EN LA RADIO REGION/LIMITES TX CALIBRACION. Ce projet ne l'utilise pas, ne l'automatise pas et ne la reproduit pas. Pour les détails, il faut aller au dépôt d'origine (https://github.com/Evgeny161rus/ftx1-region-tool, copie dans third_party/ftx1/Evgeny161rus-ftx1-region-tool).

Ce que c'est. Un outil en ligne de commande en Python qui utilise des commandes de service non documentées, présentes dans le firmware MAIN mais absentes du manuel CAT, pour lire et écrire des octets isolés de l'EEPROM de la radio. Les octets qu'il modifie sont proches de la table de calibration d'usine [Evgeny161rus-ftx1-region-tool:README.md] [Evgeny161rus-ftx1-region-tool:ftx1_region.py]. Il ne touche l'EEPROM que par ces commandes de service (SPR lecture, SPW écriture) ; il n'utilise ni menus ni commandes normales.

Ce qui change, en concept. Le code de destination ou de région de la radio. De ce code dépend la table des bandes sur lesquelles le firmware autorise l'émission. Le changer élargit ou réduit les plages de TX ; l'outil documente des tables différentes selon la région (étroite pour les bandes amateur, plus large, ou presque continue). L'outil lui-même avertit qu'une région très large peut proposer des plages où le trajet RF n'est pas prévu pour fonctionner [Evgeny161rus-ftx1-region-tool:README.md]. Il est fait pour une version précise du firmware MAIN (V01.13) ; dans d'autres versions, il faut d'abord faire un vidage car les adresses et les codes peuvent différer.

Garde-fous de l'outil. Les anciennes versions avaient un défaut de lecture qui produisait des vidages et des sauvegardes corrompus.

Firmware pris en charge.

  • Conçu pour le FTX-1 avec MAIN V01.13 : c'est de cette image que viennent la table des régions et les tables de plages de TX qu'il utilise. Sur d'autres versions, il faut d'abord faire un vidage et vérifier avec info, car les adresses et les codes peuvent différer [Evgeny161rus-ftx1-region-tool:README.md].
  • La lecture de la version utilise VE ; l'identification utilise ID (le FTX-1 répond ID0840).
  • Il n'atteint que les 64 premiers Kio de l'EEPROM (adresse sur 16 bits), sur les 128 Kio de la puce ; la région, la calibration et les réglages sont au début.

Profil FT-710. Avec --radio ft710 (ou en le choisissant dans le menu), le même outil utilise un autre profil : EEPROM SPI de 32 Kio, autre position du code et d'un indicateur « 4K », identification ID0710 et copie toujours complète avant d'écrire. Il sert à vidanger, sonder, changer la région et analyser des fichiers du FT-710 [Evgeny161rus-ftx1-region-tool:ftx1_region.py]. Sur le FT-710, le changement de région utilise en plus une commande JP ; sur le FTX-1, cette commande est un squelette qui répond ?;, c'est pourquoi on utilise ici les ordres de service de l'EEPROM.

Sous-commandes qui ne font que lire (elles ne modifient pas la radio) :

  • ports : liste les ports série et marque celui du CAT.
  • info : lit ID, la version et le code de région actuel ; affiche son nom et les plages de TX que le firmware autorise pour ce code.
  • list : tableau des codes de région connus (nom, s'il est « large » et une description) ; il est local et ne communique pas avec la radio.
  • dump : vidange l'EEPROM dans un .bin et un .txt (voir ci-dessous).
  • read : lit un seul octet de l'EEPROM.
  • probe (prévu pour le FT-710) : requêtes en lecture seule de ID, VE, JP et lectures de l'EEPROM ; enregistre un journal dans le dossier des vidages et indique si le vidage complet par CAT est possible.
  • analyze : analyse hors ligne un .bin déjà enregistré (taille, région, blocs non vides) et, avec --diff, le compare à un autre.
  • hardware : n'imprime que des instructions pour un vidage avec programmateur externe (puce SPI du FT-710, CH341A et pince SOP8, deux vidages et comparer l'empreinte, ne pas appliquer 5 V à une puce de 3,3 V).
  • patch : hors ligne, change le code de région dans une copie d'un vidage et enregistre un nouveau fichier ; il ne touche pas à la radio, mais le résultat est prévu pour être gravé avec un programmateur externe (REGION/LIMITES TX).

Sous-commandes qui écrivent :

  • set : change le code de région (ESCRIBE EN LA RADIO REGION/LIMITES TX). Accepte le code ou le nom, ou le demande en affichant le tableau.
  • write : écrit un seul octet à n'importe quelle position de l'EEPROM, y compris la calibration (ESCRIBE EN LA RADIO REGION/LIMITES TX CALIBRACION) ; c'est une option pour experts et elle ne doit pas être utilisée à l'aveugle.
  • L'option de menu « set » (sans arguments) fait la même chose que set.

Vidage et copies.

  • Le vidage se lit octet par octet, à environ 12 ms par octet : le vidage normal (les 4 premiers Kio : en-tête, calibration et région) prend environ 50 s et le complet de 64 Kio (--full) environ 13 minutes. --double lit deux fois et compare.
  • À côté du .bin, il enregistre un .txt avec la date, le port, l'identification, le firmware, la région, la somme SHA-256 et le nombre d'octets en échec.
  • Sans --out, les vidages vont dans le dossier dumps à côté du script, et les copies automatiques préalables à l'écriture dans le dossier backups ; les deux se créent tout seuls et le chemin complet est imprimé à la fin.
  • La copie automatique préalable à set couvre les 512 premiers octets de l'EEPROM (en-tête, calibration et région) ; sur le FT-710, c'est toujours l'EEPROM complète.

Garde-fous.

  • set --dry-run : affiche le code actuel et le nouveau avec leurs plages et s'arrête sans rien écrire.
  • Si le code actuel est inconnu, il refuse d'écrire sauf avec --force.
  • Copie automatique préalable et sa vérification : si un octet ne se lit pas ou si la région de la copie ne coïncide pas avec l'actuelle, il annule (--no-backup l'omet).
  • Confirmation explicite (il faut taper yes ; --yes l'omet).
  • Relecture après l'écriture, avec réessais et pauses, car le firmware change de tables juste après ; si la lecture est impossible, il avertit avec write sent, but the readback failed (ce n'est pas une erreur d'écriture).
  • Il faut éteindre et rallumer complètement la radio et regarder de nouveau avec info. Si le code revient en arrière, le firmware le restaure au démarrage et il faudrait un programmateur externe.
  • Les erreurs CAT ne ferment pas le menu ; elles sont seulement imprimées.

Défauts connus et corrigés. Le 2026-11-09, la lecture de SPR a été corrigée : la réponse était lue jusqu'au premier ;, mais cet octet peut aussi être une donnée ou la somme de contrôle, de sorte que le flux se décalait et que les réponses suivantes correspondaient à des adresses précédentes avec la bonne somme. Résultat : vidages et copies corrompus, et set qui écrivait puis échouait à la vérification. Désormais, on lit une réponse de longueur fixe, on vide le tampon et on réessaie, on vérifie la copie préalable et aussi ID. Les vidages antérieurs ont été marqués _CORRUPT et ne servent pas à restaurer [Evgeny161rus-ftx1-region-tool:README.md].

Commandes CAT cachées qu'il documente. Après la table ordonnée des commandes du firmware MAIN, l'outil décrit un bloc de commandes cachées : DP, SP, EO, FD, KT, PE, ZZ, VE, JP, A0, A1, A2, RL, EX et SW. Seuls les noms sont cités ; ceux utilisés par l'outil sont SPR et SPW (lecture et écriture d'un octet de l'EEPROM), et SPIR répond sur la vraie radio [Evgeny161rus-ftx1-region-tool:README.md].

juanmmmmmmm-Look4Sat-FTX1 est un fork expérimental de Look4Sat avec « Yaesu FTX-1 » comme modèle de radio, par USB OTG direct (sans PC ni rigctld). ESCRIBE EN LA RADIO (VFO, mode, split et CTCSS) ; on n'a trouvé ni REGION/LIMITES TX, ni CALIBRACION, ni FIRMWARE [juanmmmmmmm-Look4Sat-FTX1:README.md].

  • Modèle : MAIN = RX/descente, SUB = TX/montée [juanmmmmmmm-Look4Sat-FTX1:core/data/src/main/java/com/rtbishop/look4sat/core/data/framework/RadioTrackingService.kt].
  • Démarrage : mode MAIN selon le mode de descente, mode SUB selon celui de montée ; fréquence SUB initiale = base de TX ou milieu de la bande de montée ; ensuite FT1; + VS1; (SUB comme côté de TX).
  • Commandes utilisées : FA%09d;, FB%09d;, MD0<codigo>;/MD1<codigo>;, FT0/1;, VS0/1;, ST1/ST0;, CN10%03d; (tonalité CTCSS sur SUB, indice 000-049, uniquement tonalités standard avec tolérance de 0.05 Hz) et CT11;/CT10; ; une vérification inoffensive FA; après 150 ms à la connexion [juanmmmmmmm-Look4Sat-FTX1:core/data/src/main/java/com/rtbishop/look4sat/core/data/framework/Ftx1CatProtocol.kt] [juanmmmmmmm-Look4Sat-FTX1:core/data/src/main/java/com/rtbishop/look4sat/core/data/framework/Ftx1Controller.kt].
  • Doppler : à chaque cycle de 1 s il calcule la position et la vitesse radiale, met en correspondance la base de montée avec la descente via le pas de bande du transpondeur linéaire et applique getUplinkFreq/getDownlinkFreq ; le décalage de descente de l'utilisateur est appliqué avant la mise en correspondance pour la montée et après pour la descente ; uniquement transpondeurs linéaires [juanmmmmmmm-Look4Sat-FTX1:core/domain/src/main/java/com/rtbishop/look4sat/core/domain/utility/DopplerFrequencyCalculator.kt].
  • Accord manuel : lit FB/FA, compare avec le dernier envoi (seuil de 20 Hz) et après deux lectures stables recalcule la base de TX et reprend les corrections.
  • FM : CTCSS uniquement dans l'encodeur de montée de SUB, configurable ; le suivi n'applique pas seul une tonalité choisie.
  • PTT : le logiciel ne l'envoie jamais (pttOn() journalise et renvoie faux) ; DTR/RTS forcés à faux ; uniquement le PTT physique du microphone.
  • stopTracking() annule seulement la tâche : il ne restaure pas la fréquence, le mode, le split, le VFO ni le CTCSS précédents.
