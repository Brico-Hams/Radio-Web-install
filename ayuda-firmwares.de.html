Was „unterstützt“ bedeutet

Es gibt vier unterschiedliche Begriffe:

  1. Vom Firmwareprojekt unterstützt: Upstream pflegt ein Image.
  2. Vom Connector erkannt: Diese Website kennt eine Identifikationsstruktur.
  3. Im Katalog veröffentlicht: Ein Dateiname aus einer autorisierten Quelle wird erkannt. Das bedeutet nicht, dass die Datei mit dieser Website installiert werden kann.
  4. Auf einem Funkgerät getestet: Dafür braucht es einen physischen Nachweis für das genaue Modell und den Build. Automatisierte Tests dieser Website sind keine solche Zertifizierung.

Eine Tabellenzeile berechtigt nicht dazu, Firmware einer anderen Revision zu verwenden. „Download“ bedeutet nicht „Flashen“; „geprüfte Datei“ bedeutet nicht „digital signiert“.

„Alle Versionen“ wird als Matrix der Familien, Unterschiede und Quellen je Version dokumentiert, nicht als Versprechen, dass jedes Menü bereits in der ersten Firmware vorhanden ist. Notiere für einen konkreten Build Modell, Revision, Datum, Dateiname, Commit (falls vorhanden) und Hash. Vergleiche Handbuch und Versionshinweise. Sicherheitsregel und gesetzmäßige Nutzung

  • Identifiziere die tatsächliche Hardware, nicht nur das Gehäuse.
  • Bewahre die Originalkalibrierung und das Codeplug vor einer Migration auf.
  • Führe Löschungen, Wiederherstellungen oder Reset nicht wegen eines Portfehlers aus, ohne zuvor die Ursache zu kennen.
  • Für OpenGD77 hält diese Website das Schreiben gesperrt, weil sie keine vollständige, verifizierte MCU-Firmware-Sicherung erhält.
  • Bei Quansheng erfordern Änderungen eine vollständige Sicherung; Main ist geschützt.
  • Importierte Empfangsdaten beginnen als RX-only.
  • Aktiviere TX nicht automatisch oder außerhalb zugelassener Frequenzen. Ein PMR-/GMRS-/FRS-/MURS-Firmwareprofil zertifiziert kein Funkgerät.

Lizenzen: getrennte Komponenten

Die Benutzerangabe „die Lizenz ist MIT“ wird als noch einer Komponente, einem Rechteinhaber und dem originalen Lizenztext zuzuordnende Erklärung festgehalten. Sie ändert weder die Lizenz Dritter noch die des bestehenden Repositorys:

  • Die Website erklärt GPL-3.0-or-later in ihrem Manifest und der Datei LICENSE.
  • Die untersuchten F4HWN-Quellen enthalten Apache-2.0 und NOTICE.
  • CHIRP-Treiber aus dem Karina-Paket enthalten GPL-Hinweise.
  • Die genaue Lizenz der Karina-Firmware erscheint nicht im untersuchten Paket. Die MIT-Angabe des Benutzers enthält keine Quellen und belegt nicht, auf welche Dateien/Versionen sie sich bezieht. Der entsprechende Hinweis wird ergänzt, sobald es eine überprüfbare Referenz gibt.
  • OpenGD77 und seine Komponenten unterliegen ihren eigenen Hinweisen; MIT nicht voraussetzen.

Vollständige Handbücher, Karina-Firmware, fremde Kalibrierungen oder Software Dritter werden nicht allein deshalb weiterverteilt, weil sie zitiert werden.

Diese Bibliothek aktualisieren

Wertetabellen werden aus festgelegten Katalogen generiert, nicht aus dem Gedächtnis:

npm run build:help

Wenn ein Katalog geändert wird, müssen Bedeutung neuer Optionen, Versionen und Abhängigkeiten geprüft, die Seiten neu generiert und die Hilfetests ausgeführt werden. Beim Öffnen eines Leitfadens wird weder das Funkgerät abgefragt noch seine Konfiguration geändert.

Der historische Snapshot befindet sich in f4hwn-history-presets.json: Er speichert Commit, SHA-256 und Inhalt von CMakePresets.json für jede Version. Seine Aktualisierung erfolgt ausdrücklich mit node scripts/fetch-help-presets.cjs aus dem Repository-Stammverzeichnis; dies ruft öffentliche Daten von GitHub ab, greift jedoch nicht auf Funkgeräte zu und lädt keine lokalen Dateien hoch. Der normale Hilfegenerator funktioniert offline und lädt keine Quellen herunter.
