Egzumer: source, configuration, and differences from V3

Revision: 25-10-2026. Inspected source: egzumer/uv-k5-firmware-custom, commit 7607f0a4bd6203d1f06b70556fc1ce0d7399d6b3.

What this repository provides

It publishes C code, headers, a Makefile, and documentation for a reimplementation of the original-family Quansheng UV-K5/K6/5R firmware. The README explains the origins of DualTachyon, OneOfEleven modifications, and the fagci analyzer. This codebase is not the PY32 port for UV-K5 V3/UV-K1.

Its LICENSE contains Apache License 2.0, not MIT. Preserve its notices, attributions, and those of components when deriving code. Egzumer's license does not show that another image called Karina uses the same license or that the exact sources for that binary are available.

Do not use a V1 flasher or original Egzumer image on a V3. K5/K6 in a title does not prove the MCU revision. Check the board and project. The Bricohams V3 command does not include an Egzumer compiler.

Features and user settings

The README documents AM correction, SSB demodulation, spectrum, fast scanning, name editing, display modes, assignable keys, battery, backlight, microphone, and CTCSS/DCS search. SSB here describes receive demodulation; it does not mean an SSB transmitter.

For RX/TX, step, bandwidth, SQL, tones, VOX, TOT, and channel lock concepts, see common configuration. Use the menu name, not numbers carried over from F4HWN v6 or Karina. The order and names were changed from stock firmware.

The official wiki is the reference for key sequences in the installed build:

  • Wiki and manual.
  • Releases.

Not all its shortcuts have been verified on hardware, and they are not automatically carried over to derivative firmware. The README warns of dynamic range limits, overload, and input filters; AM fix cannot eliminate physical limits. An antenna with more signal can worsen reception in a strong RF environment.

In that Makefile, Clang forces LTO=0; with LTO=1, OVERLAY=0 is forced. These rules belong to this codebase and must not be copied to PY32 CMake without analysis. Enabling options can exceed memory or break combinations; the existence of an option does not imply support for every combination.

To build, use the toolchain and procedure in its README in a pinned checkout; preserve the map, license, and hashes, and validate on V1 hardware. Egzumer was not built, flashed, or tested during this documentation addition.

Relationship to Karina and Bricohams

A genealogy of similar features cannot reconstruct Karina's exact sources. Drivers and names mentioned by Egzumer are not proof either. Bricohams V3 currently derives from F4HWN PY32, not this original repository. A Bricohams V1 project would be a different build and require separate hardware validation.
